# 模型与输出的商用授权核对清单

> 本文档只提供**核对框架与留档口径**，不构成法律意见。权重、节点与第三方组件的许可由其各自发布方提供，且会变更；一律以交付当日的官方发布页 / LICENSE 文件为准。

## 为什么需要单独留档

本项目是本地优先的兼容工具：应用本身不下载、不复制、不重新组织模型文件，模型由使用者自行放置。因此商用交付时，授权链不在应用里自动成立，而是由三层叠加：

| 层 | 覆盖范围 | 需要核对什么 |
|---|---|---|
| 应用代码 | 本仓库及其依赖 | 仓库 LICENSE 与依赖许可；本仓库为独立兼容工具，与模型厂商无隶属关系 |
| 模型权重 | 扩散模型、文本编码器、VAE、LoRA、预览模型 | 每一份权重自带的许可文件、商用条款、地域与营收限制、是否允许微调与下游分发 |
| 第三方组件 | ComfyUI 本体、自定义节点包、ffmpeg、字体与素材 | 各自许可证、节点包是否声明兼容范围、素材版权与肖像/商标权 |

项目 README 已声明模型权重与第三方组件不受本仓库许可覆盖。

## 内置能力涉及的模型族（按工作区）

| 工作区 | 涉及的模型 / 组件 | 交付前重点核对 |
|---|---|---|
| H3 视频（文生 / 图生 / 首尾帧 / 续写） | FL2VA、Ref2VA 检查点、Turbo LoRA（4/8 步）、Qwen3-VL 文本编码器、视频与音频 VAE | 社区许可常有地域、营收与商用边界；LoRA 若来自第三方仓库，需单独核对许可与来源 |
| LTX 2.5 视频 | LTX 2.5 检查点、潜空间 2× 上采样器、LTX VAE | 模型许可与配套上采样权重许可可能不同 |
| 图像工作区 | Z-Image Turbo / Base、Qwen-Image 2.1 / 2512、MOSS-Image（含 edit LoRA）、Flux.1-dev，以及用户自定义注册模型 | 自定义注册模型不在内置目录，容易漏记来源；编辑用 LoRA 需单独留档 |
| ACE-Step 音乐 | XL SFT / XL Base 检查点 | 音乐输出的使用范围与训练数据条款 |
| 通用 | ComfyUI 自定义节点、ffmpeg 可执行文件、参考素材 | 节点包许可、素材版权、真实 logo / 署名 / 地理标志 |

## 每次商用交付的留档字段

建议在工程目录随成片保存一份纯文本记录，至少包含：

- 交付日期、客户 / 项目名称、成片文件列表
- 各工作区使用的 provider id、权重文件名、LoRA 文件名与强度、seed、分辨率、时长
- 每一份权重 / LoRA 的**来源链接与许可快照**（链接 + 核对日期），不要只写模型名
- 参考素材来源与授权说明；若使用了真实商标、署名或地理标志，记录替换与去标识处理
- 输出归属条款的核对结论（是否允许客户下游使用、是否需要标注）

本地固定 seed、逐文件 pin、提示词库与工作流 JSON 已能还原生成参数；把它们与上面的授权记录一起归档，即可构成「参数可复现 + 许可可追溯」的交付证据链。

## 仍未自动化的部分

当前应用不会读取权重目录里的 LICENSE 文件，也不会在导出时自动附带授权记录；上表字段需人工核对并留档。若后续要做自动化，应只做「读取并展示已有许可文件」，不要由应用替用户判定商用可行性。
